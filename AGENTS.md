# AGENTS.md

`agent-kit` — установщик шаблонных правил, скиллов, команд и агентов для ИИ-агента. Это
**не PHP-проект**, несмотря на путь: установка и тесты — Python 3 (только стандартная
библиотека), `sh` остался только в `bootstrap.sh`. Kit копирует файлы в целевой проект и ничего
не трогает глобально.

## Проверка (в том же порядке, что CI)

```sh
dash -n bootstrap.sh
shellcheck -s sh bootstrap.sh                    # локально может отсутствовать
python3 -m compileall -q install.py kit tests
python3 tests/smoke.py
```

`python3 tests/smoke.py` — единственная точка входа: обычный `unittest` по модулям `tests/`
(156 тестов, ~4 с). `tests/smoke.py` только собирает и запускает их; `python3 tests/smoke.py
test_merge` гоняет один модуль, `python3 -m unittest discover -s tests -t .` — то же без
обёртки. Юнит-тесты `kit/` (`test_common`, `test_components`, `test_render`, `test_merge`) не
трогают диск вне `tempfile`; интеграционные (`test_install`, `test_bootstrap`) запускают
`install.py` и `bootstrap.sh` отдельными процессами в одноразовых каталогах. Тесты требуют `git`
(создают проекты через `git init` и локальный «origin» для `bootstrap.sh`) и не оставляют следов
в `$HOME` — есть проверки, что установка в `$HOME` и `/` запрещена.

## Что kit правит в чужом

`opencode.json` — единственный файл за пределами путей с префиксом, который kit меняет. В нём
дополняется только `instructions[]`: пути правил `base` и выбранных групп. Существующие
записи и их порядок, остальные ключи и форматирование (отступ, CRLF, однострочный JSON)
сохраняются; повторный запуск файл не трогает. Если в проекте есть `opencode.jsonc` или конфиг
не разбирается как JSON, файл не меняется — печатаются пути для ручной вставки.
`openspec/config.yaml` и `.gitignore` kit не трогает.

`AGENTS.md` создаётся один раз из `snippets/AGENTS.md.tmpl`, если файла нет (симлинк считается
существующим), и дальше не перезаписывается.

## Устройство

- `install.py` — единственная команда `install` (по умолчанию) и `--dry-run`; сам ничего не
  клонирует. `bootstrap.sh` (POSIX `sh`) клонирует kit в `<проект>/.agent-kit`, вызывает
  `python3 install.py` и после успешной установки удаляет клон: в проекте остаются только
  поставленные файлы. Клон не удаляется, если установка упала (по нему видно, что сломалось), если
  в нём есть незакоммиченные изменения (рабочий клон) или если `AGENT_KIT_DIR` указывает вне
  проекта. `install.py` ставит `sys.dont_write_bytecode`, чтобы `kit/__pycache__` не делал клон
  грязным.
- `kit/` — пакет установки, импортируется через `sys.path[0]` (каталог `install.py`), поэтому не
  зависит от `PYTHONPATH` и текущего каталога: `common.py` (префикс, вывод, границы записи),
  `components.py` (группы и раскладка), `render.py` (ссылки и атомарная запись), `merge.py`
  (дополнение `instructions[]`).
- `components/` — **исходники** шаблонов. Группа — каталог `components/<группа>/` с
  подкаталогами `rules/`, `skills/`, `commands/`, `agents/` (подкаталог может отсутствовать).
  `base` ставится всегда, языковые группы — флагом `--with php,js`.
- Целевой путь вычисляет `kit/components.py:target_path(prefix, rel)`:
  `rules/X.md` → `.agents/rules/alxmrz_kit_X.md`,
  `skills/<id>/...` → `.agents/skills/alxmrz_kit_<id>/...`,
  `commands/X.md` → `.opencode/commands/alxmrz_kit_X.md`,
  `agents/X.md` → `.opencode/agents/alxmrz_kit_X.md`. Префикс `PREFIX` живёт в `kit/common.py`.
- `kit/render.py` при копировании переписывает ссылки внутри компонентов (`refs`) на
  префиксованные пути. Других режимов рендеринга нет.
- `kit/merge.py` дополняет `instructions[]` в `opencode.json` путями правил и **создаёт** файл,
  если его нет. Возвращает `MergeResult(status, added)` вместо кодов 0/2/3. Свойства, которые
  нельзя ломать: чужие ключи и записи не меняются, отступ/CRLF/однострочность сохраняются, при
  отсутствии изменений файл не перезаписывается.
- Учёта поставленного нет: ни манифеста, ни хешей, ни `status`/`uninstall`/`adopt`. Повторная
  установка просто перезаписывает файлы kit-а.

## Правила правки компонентов

- В `components/` ссылки пишите в **исходном** виде: `docs/general_rules.md`,
  `docs/php_rules.md`, `.agents/skills/spec-authoring`. Префикс и реальные пути подставит
  `kit/render.py`; если написать `alxmrz_kit_...` вручную, получится двойной префикс.
- Новый компонент = файл в нужном подкаталоге группы (`rules/`, `skills/<id>/`, `commands/`,
  `agents/`). Ничего в `install.py` перечислять не нужно: список даёт обход по выбранным
  группам. Служебные файлы с точкой в начале имени (`.gitkeep`) пропускаются.
- `rules/`, `commands/` и `agents/` — плоские: вложенный путь становится частью имени
  команды/агента, поэтому это ошибка компонента и прерывает установку.
- Скиллы `openspec-*` намеренно не входят в kit (их создаёт `openspec init`).
- Изменения в файлах с префиксом `alxmrz_kit_` в целевом проекте не сохраняются: установка
  перезаписывает их содержимым из `components/`. `--keep-modified`/`--force` больше нет.
- `VERSION` — одна строка, `install.py` печатает её в шапке и в `--help`. Бампа нет: версия
  информативная.

## Конвенции

- Текст, комментарии, вывод и документация — по-русски; `description` скиллов — по-английски.
- Python — только стандартная библиотека, 3.9+ (`from __future__ import annotations`, без
  runtime-`|`). Ошибки установки поднимают `KitError`; `main` печатает `ERROR:` и возвращает 1.
- `bootstrap.sh` — строго POSIX `sh` (CI проверяет `dash -n` и `shellcheck`): никакого `[[ ]]`,
  массивов, `local`, `pipefail`. Логики установки в нём нет — только проверки, клон и вызов
  `install.py`.
- Запись в проект атомарная (временный файл + `os.replace`) и только внутрь проекта: не
  ослабляйте `refuse_symlink`, `in_project`, `resolve_project_dir`.
- Идемпотентность обязательна: повторный запуск не должен давать дифф в git (побайтовое сравнение
  в `write_if_changed`, поэтому у неизменённых файлов не дёргается mtime).
