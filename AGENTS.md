# AGENTS.md

`agent-kit` — установщик шаблонных правил, скиллов, команд и агентов для ИИ-агента. Это
**не PHP-проект**, несмотря на путь: код — строгий POSIX `sh` (`dash`). Kit копирует файлы
в целевой проект и ничего не трогает глобально.

## Проверка (в том же порядке, что CI)

```sh
dash -n install.sh bootstrap.sh lib/*.sh tests/smoke.sh
shellcheck -s sh install.sh bootstrap.sh lib/*.sh tests/smoke.sh   # локально может отсутствовать
./tests/smoke.sh
```

`./tests/smoke.sh` — единственный тест: 80 проверок, ~15 с. Он гоняет установку на одноразовых
каталогах в `mktemp -d` (чужие файлы, перезапись, идемпотентность, `--with`, `commands/`/`agents/`,
`AGENTS.md`, `.gitignore`, границы записи, `--dry-run`, `bootstrap.sh` с удалением клона).
Отдельного прогона одного теста нет: скопируйте блок `# --- N.` во временный скрипт или
временно закомментируйте остальные. Тест требует `git` (создаёт проекты через `git init` и
локальный «origin» для `bootstrap.sh`) и не должен оставлять следов в `$HOME` — есть проверки,
что установка в `$HOME` и `/` запрещена.

## Что kit правит в чужом

Ничего. Файлы kit-а создаются только по путям с префиксом, `AGENTS.md` создаётся один раз из
`snippets/AGENTS.md.tmpl`, если файла нет (симлинк считается существующим), и дальше не
перезаписывается. `.gitignore` kit не читает и не меняет: клон `bootstrap.sh` удаляется после
установки, поэтому игнорировать нечего. `opencode.json` и `openspec/config.yaml` тоже не
трогаются: правила подключает `AGENTS.md`, а если `AGENTS.md` уже был — установка печатает пути
для `instructions[]`.

## Устройство

- `install.sh` — единственная команда `install` (по умолчанию) и `--dry-run`; сам ничего не
  клонирует. `bootstrap.sh` клонирует kit в `<проект>/.agent-kit`, вызывает `install.sh` и после
  успешной установки удаляет клон: в проекте остаются только поставленные файлы. Клон не
  удаляется, если установка упала (по нему видно, что сломалось), если в нём есть
  незакоммиченные изменения (рабочий клон) или если `AGENT_KIT_DIR` указывает вне проекта.
- `lib/*.sh` подключаются через `.` из `install.sh`; отдельно не запускаются.
- `components/` — **исходники** шаблонов. Группа — каталог `components/<группа>/` с
  подкаталогами `rules/`, `skills/`, `commands/`, `agents/` (подкаталог может отсутствовать).
  `base` ставится всегда, языковые группы — флагом `--with php,js`.
- Целевой путь вычисляет `lib/components.sh:target_path`:
  `rules/X.md` → `.agents/rules/alxmrz_kit_X.md`,
  `skills/<id>/...` → `.agents/skills/alxmrz_kit_<id>/...`,
  `commands/X.md` → `.opencode/commands/alxmrz_kit_X.md`,
  `agents/X.md` → `.opencode/agents/alxmrz_kit_X.md`. Префикс `PREFIX` живёт в `lib/common.sh`.
- `lib/render.sh` при копировании переписывает ссылки внутри компонентов (`refs`) на
  префиксованные пути. Других режимов рендеринга нет.
- Учёта поставленного нет: ни манифеста, ни хешей, ни `status`/`uninstall`/`adopt`. Повторная
  установка просто перезаписывает файлы kit-а.

## Правила правки компонентов

- В `components/` ссылки пишите в **исходном** виде: `docs/general_rules.md`,
  `docs/php_rules.md`, `.agents/skills/spec-authoring`. Префикс и реальные пути подставит
  `render.sh`; если написать `alxmrz_kit_...` вручную, получится двойной префикс.
- Новый компонент = файл в нужном подкаталоге группы (`rules/`, `skills/<id>/`, `commands/`,
  `agents/`). Ничего в `install.sh` перечислять не нужно: список даёт `find` по выбранным
  группам. Служебные файлы с точкой в начале имени (`.gitkeep`) пропускаются.
- `rules/`, `commands/` и `agents/` — плоские: вложенный путь становится частью имени
  команды/агента, поэтому это ошибка компонента и прерывает установку.
- Скиллы `openspec-*` намеренно не входят в kit (их создаёт `openspec init`).
- Изменения в файлах с префиксом `alxmrz_kit_` в целевом проекте не сохраняются: установка
  перезаписывает их содержимым из `components/`. `--keep-modified`/`--force` больше нет.
- `VERSION` — одна строка, `install.sh` печатает её в шапке и в `--help`. Бампа нет: версия
  информативная.

## Конвенции

- Текст, комментарии, вывод и документация — по-русски; `description` скиллов — по-английски.
- Скрипты — строго POSIX `sh` (CI проверяет `dash -n`): никакого `[[ ]]`, массивов, `local`,
  `pipefail`. Ошибки в пайпе обязаны прерывать установку — поэтому списки собираются в файлы,
  а не через `| while`.
- Запись в проект атомарная (временный файл + `mv`) и только внутрь проекта: не ослабляйте
  `refuse_symlink`, `in_project`, `resolve_project_dir`.
- Идемпотентность обязательна: повторный запуск не должен давать дифф в git (сравнение через
  `cmp`, поэтому у неизменённых файлов не дёргается mtime).
