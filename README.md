# agent-kit

Шаблонные файлы для работы с ИИ-агентом в проекте: правила кода, скиллы, команды, агенты и
заготовка `AGENTS.md`. Ставится внутрь проекта, ничего глобального не трогает.

Каждый файл получает префикс `alxmrz_kit_`, поэтому не сталкивается с вашими одноимёнными
правилами, скиллами, командами и агентами.

## Установка в новый проект

```sh
curl -fsSL https://raw.githubusercontent.com/alxmrz/agent-kit/main/bootstrap.sh | sh
```

Команда клонирует kit в `./.agent-kit/` (добавляется в `.gitignore`) и запускает установку.
Языковую специфику можно подключить сразу:

```sh
curl -fsSL https://raw.githubusercontent.com/alxmrz/agent-kit/main/bootstrap.sh | sh -s -- --with php
```

Повторный запуск обновляет клон и перезаписывает файлы kit-а:

```sh
./.agent-kit/install.sh                 # обновить (только base)
./.agent-kit/install.sh --with php,js   # base + php + js
./.agent-kit/install.sh --dry-run       # показать план
```

Без сети:

```sh
sh ./.agent-kit/bootstrap.sh --offline
```

Удаления одной командой нет: kit не ведёт учёт поставленного. Уберите файлы с префиксом
`alxmrz_kit_` из `.agents/` и `.opencode/` вручную.

## Что появляется в проекте

| Путь | Назначение |
| --- | --- |
| `.agents/rules/alxmrz_kit_general_rules.md` | общие правила написания кода |
| `.agents/rules/alxmrz_kit_php_rules.md` | PHP-специфика (группа `php`) |
| `.agents/skills/alxmrz_kit_conventional-commit/` | скилл коммитов |
| `.agents/skills/alxmrz_kit_spec-authoring/` | скилл спек и дизайна |
| `.opencode/commands/alxmrz_kit_<имя>.md` | команды (когда появятся в группе) |
| `.opencode/agents/alxmrz_kit_<имя>.md` | агенты (когда появятся в группе) |
| `AGENTS.md` | создаётся один раз, если его нет |
| `.gitignore` | добавляется `.agent-kit/` |

## Группы

Группа — каталог `components/<группа>/`. `base` ставится всегда, остальные подключаются
`--with`. Флаг можно повторять: `--with php --with js`, и указывать список через запятую:
`--with 'php, js'`. Неизвестная группа — ошибка до первой записи, в проект не попадает
ничего.

Доступные группы: `base`, `php`.

## Гарантии

- **Только проект.** Домашний каталог (в любом написании пути) и корень файловой системы
  отвергаются, глобальные `~/.agents` и `~/.config/opencode` не читаются и не изменяются.
  Симлинки вместо kit-файлов отвергаются: запись никогда не уезжает за пределы проекта.
- **Перезапись безусловная.** Файл с префиксом `alxmrz_kit_` всегда приводится к содержимому
  из `components/`. Правки в таких файлах не сохраняются — своё держите в файлах без префикса.
- **Чужие файлы неприкосновенны.** Всё, что не имеет префикса `alxmrz_kit_`, не читается и не
  перезаписывается. `opencode.json` и `openspec/config.yaml` kit не трогает.
- **Повторный запуск идемпотентен.** Если kit не менялся, диффа в git не будет.
- **Правила подключает `AGENTS.md`.** В проект без `AGENTS.md` он создаётся из шаблона со
  ссылкой на правила. Если `AGENTS.md` уже был, установка печатает пути для `instructions[]`
  файла `opencode.json`.

## Флаги

| Флаг | Действие |
| --- | --- |
| `--dir <каталог>` | целевой проект (по умолчанию текущий) |
| `--with <группы>` | дополнительные группы через запятую; можно повторять |
| `--dry-run` | показать план, ничего не записывая |

`bootstrap.sh` дополнительно понимает `--offline` (не обновлять клон).

## Переменные окружения

`bootstrap.sh` понимает `AGENT_KIT_REPO`, `AGENT_KIT_REF` и `AGENT_KIT_DIR` —
удобно для форка или проверки ветки.

## Состав репозитория

```
bootstrap.sh                  точка входа: clone -> install.sh
install.sh                    установка
lib/                          общие функции, группы, рендеринг ссылок
components/base/              всегда ставимая группа
components/php/               языковая группа (--with php)
snippets/                     шаблон AGENTS.md
tests/smoke.sh                автопроверка на одноразовых каталогах
```

Раскладка `components/<группа>/<тип>/`: `rules/`, `skills/`, `commands/`, `agents/`.
Подкаталог может отсутствовать; новый файл подхватывается без правки скрипта.

## Требования

`sh`, `git`. Для `bootstrap.sh` нужен `git`; `install.sh` в сеть не ходит и внешних
зависимостей не требует.

## Развитие kit-а

Компоненты — обычные файлы в `components/<группа>/`. Положите файл в нужный подкаталог и
проверьте установку:

```sh
./tests/smoke.sh
```

OpenSpec-скиллы (`openspec-*`) намеренно не входят в kit: их создаёт `openspec init`.
