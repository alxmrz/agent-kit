# Proposal

## Why

Установка сейчас размазана по POSIX `sh`: `install.sh` (298 строк) плюс `lib/common.sh`,
`lib/components.sh` и `lib/render.sh`, которые подключаются через `.` и делят одно глобальное
пространство имён. Из-за ограничений `dash` (`local` нет, массивов нет, `pipefail` нет) списки
групп, источников и целей складываются в файлы во временном каталоге, значения возвращаются
через `printf` и `$(...)`, а ошибки в пайплайнах обходятся руками. Читать такую установку дорого:
часть логики уже написана на Python (`lib/merge.py`), и проект вынужден держать два рантайма и
два набора приёмов в одном продукте.

Нужно оставить на `sh` только то, что этого требует: `bootstrap.sh`, который запускают как
`curl … | sh` на чистой машине. Остальное — обычный Python-пакет, который проще читать, тестировать
и расширять.

## What Changes

- **BREAKING**: вход установки — `install.py` (`python3 install.py [install] [флаги]`) вместо
  `./install.sh`. `bootstrap.sh` вызывает его сам, поэтому пользователь `curl … | sh` разницы не
  видит; меняется только локальный запуск из клона и печатаемая подсказка «Обновить».
- **BREAKING**: `python3` становится обязательной зависимостью (раньше был необязательным: без него
  `opencode.json` не правился). `bootstrap.sh` проверяет `python3` до клонирования и падает с
  внятным сообщением, ничего не записав в проект.
- `lib/common.sh`, `lib/components.sh`, `lib/render.sh`, `lib/merge.py` заменяются Python-пакетом
  `kit/`: вывод и границы записи, группы и раскладка путей, копирование компонентов, слияние
  `instructions[]`. Логика переезжает один в один — это перенос, а не переделка.
- Поведение установки не меняется: те же флаги (`install`, `--dir`, `--with`, `--dry-run`,
  `--help`), тот же формат вывода (`== `, `OK`/`SKIP`/`WARN`), те же коды возврата (0/1, 130 при
  прерывании), та же безусловная перезапись, тот же `cmp`-пропуск перезаписи (идемпотентность),
  те же границы записи (только проект, `$HOME` и `/` запрещены, симлинки не перезаписываются).
- `tests/smoke.sh` переписывается на Python (`tests/smoke.py`) с тем же набором проверок, чтобы
  тесты не оставались единственным островком `sh`. Запуск — `python3 tests/smoke.py`.
- CI: `dash -n`/`shellcheck` остаются только для `bootstrap.sh`; добавляется проверка
  компиляции Python-модулей.

## Capabilities

### New Capabilities

- `install-runtime`: на чём работает установка — обязательный Python 3, вход через `install.py`,
  сохранение CLI-контракта и кодов возврата, подсказки, которые ведут на существующие файлы.
- `bootstrap-launcher`: `bootstrap.sh` как POSIX `sh`-точка входа для `curl … | sh` — проверка
  `python3` до клонирования и вызов `install.py` вместо `install.sh`.

### Modified Capabilities

Нет: в `openspec/specs/` пока ни одной капабилити нет, спецификации прошлых изменений ещё
не синхронизированы.

## Impact

- Удаляются: `install.sh`, `lib/common.sh`, `lib/components.sh`, `lib/render.sh`, `lib/merge.py`,
  `tests/smoke.sh`.
- Появляются: `install.py` (CLI и шаги установки), `kit/__init__.py`, `kit/common.py`,
  `kit/components.py`, `kit/render.py`, `kit/merge.py`, `tests/smoke.py`.
- `bootstrap.sh`: вызов `python3 "$KIT_DIR/install.py"`, предварительная проверка `python3`
  (перед `git clone`), остальное без изменений.
- `.github/workflows/ci.yml`: `dash -n` и `shellcheck` только по `bootstrap.sh`; `python3 -m compileall`
  по `install.py`, `kit/`, `tests/`; тесты через `python3 tests/smoke.py`.
- `README.md`, `AGENTS.md`, `snippets/AGENTS.md.tmpl` (если упоминают проверки): состав
  репозитория, требования (`python3` обязателен), команда проверки и запуска.
- Для пользователя kit-а: ничего не ломается, кроме запуска из клона — вместо `./install.sh`
  нужен `python3 install.py` (обновление идёт через `bootstrap.sh`, его это не касается).
