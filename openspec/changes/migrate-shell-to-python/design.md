# Design

## Context

См. `proposal.md` — Why. Текущее устройство, которое определяет перенос:

- `install.sh` держит CLI, порядок шагов и весь вывод; `lib/*.sh` делят с ним глобальные
  переменные (`COMMON` `PREFIX`, `STATE_DIR`, `PROJECT_DIR`, `DRY_RUN`). Вызовы продолжают
  друг друга через побочные эффекты и файлы во временном каталоге.
- `pipelines`/циклы `while` вынесены в файлы, потому что в `dash` пайплайн создаёт подоболочку.
- `lib/merge.py` уже Python и вызывается отдельным процессом с кодами 0/2/3.
- `bootstrap.sh` — POSIX `sh`, запускаемый через `curl | sh`; удаляет свой клон и
  пробрасывает аргументы в `install.sh`.
- `tests/smoke.sh` — единственный тест: 103 проверки, ~20 с, одноразовые каталоги в `mktemp -d`.
- Контракт, который нельзя потерять: флаги, формат вывода, коды 0/1/130, безусловная перезапись
  с `cmp`-пропуском (идемпотентность), границы записи, отказ от симлинков, поведение с чужим
  `opencode.json`.

## Goals / Non-Goals

**Goals:**

- Один язык для установки и тестов; отсутствие глобального состояния между модулями.
- Побайтово тот же результат установки: те же файлы, тот же вывод, те же коды возврата.
- Python-код, который читается сверху вниз: явные аргументы и возвращаемые значения вместо
  файлов во временном каталоге и переменных-соглашений.

**Non-Goals:**

- Не меняем раскладку компонентов, набор групп, формат `instructions[]`, текст подсказок
  (кроме имени запускаемого файла).
- Не вводим конфиг-файл kit-а, плагины, асинхронность, зависимости из PyPI.
- Не переписываем `bootstrap.sh` на Python: он обязан работать до установки Python-зависимостей
  и запускаться через `sh`.
- Не добавляем учёт поставленного (`status`/`uninstall`), не возвращаем манифест.

## Decisions

### 1. Раскладка: `install.py` + пакет `kit/`

```
install.py          CLI: разбор аргументов, шаги установки, main()
kit/__init__.py
kit/common.py       PREFIX, вывод (step/ok/skip/warn/die), пути и границы записи
kit/components.py   группы, поиск источников, target_path
kit/render.py       переписывание ссылок, атомарная запись с пропуском неизменного
kit/merge.py        дополнение instructions[] (перенос текущего lib/merge.py)
tests/smoke.py      автопроверка
```

`install.py` остаётся точкой входа, потому что её путь знает `bootstrap.sh` и её печатают
подсказки. Пакет рядом импортируется через `sys.path[0]` (каталог скрипта), поэтому установка не
зависит от `PYTHONPATH` и от текущего каталога. Альтернатива — `python3 -m kit` — отвергнута: она
ломает локальную команду и подсказку «Обновить», ради незначительного выигрыша.

Модули повторяют бывшие `lib/*.sh` один в один, но принимают и возвращают значения:

- `components.list_groups(components_dir)` → `list[str]`;
- `components.list_sources(components_dir, groups)` → `list[str]` (отсортированные пути
  относительно `components/`, без файлов, начинающихся с точки);
- `components.target_path(prefix, rel)` → целевой путь, `ValueError`/ошибка на вложенность в
  `rules/`, `commands/`, `agents/`;
- `render.copy_component(components_dir, project_dir, src, dst)`.

### 2. Обязательный Python 3 и вход через `install.py`

Версия: Python 3.9+ (аннотации `from __future__ import annotations`, без runtime-`. `|`).
`bootstrap.sh` делает `command -v python3` до клонирования и печатает `ERROR: нужен python3`.
Внутри Python проверка версии не нужна: синтаксис сам даст понятную ошибку на слишком старом
интерпретаторе. Шаг «python3 не найден» из `opencode.json` удаляется: без Python установка вообще
не идёт. Это осознанное ужесточение, зафиксированное в proposal.

### 3. Временные файлы вместо `$STATE_DIR`

`install.py` создаёт `tempfile.mkdtemp()` и удаляет его в `finally`. Списки групп, источников и
целей живут как `list[str]`/`set[str]` в памяти; файлы нужны только там, где нужен внешний
процесс — но внешних процессов больше нет, поэтому временный каталог остаётся только для
`AGENTS.md` (проще собрать строку и записать атомарно).

`sys.exit(130)` реализуется через обработчики `signal` для `SIGHUP`/`SIGINT`/`SIGTERM`, которые
поднимают `KeyboardInterrupt`; `main` ловит его, убирает временные файлы и возвращает 130.
Обработчик не делает `os._exit`: иначе `finally` и удаление временных файлов не выполнятся.

### 4. Атомарная запись и идемпотентность

`render.write_if_changed(path, data: bytes, mode: int)`:

1. если файл существует, является обычным файлом (не симлинком) и его байты равны `data` —
   ничего не делать;
2. иначе писать `path.with_name(path.name + f".tmp.{os.getpid()}")` в том же каталоге,
   выставить `mode`, `os.replace` на целевой путь.

Сравнение именно байтовое (не `cmp` через процесс и не `filecmp` с `shallow`), чтобы повторный
запуск гарантированно не трогал `mtime`. Временный файл удаляется в `finally`, поэтому обрыв
не оставляет мусора. Симлинк проверяется до записи (`os.path.islink`) — `os.replace` заменил бы
симлинк, поэтому отказ явный и с тем же текстом, что раньше.

Права доступа берутся у источника (эквивалент `cp -p`), как раньше: у `scripts/` рядом со
`SKILL.md` они бывают исполняемыми.

### 5. Переписывание ссылок — регулярные выражения вместо `sed`

Ссылки переписываются в памяти: `read_bytes().decode("utf-8")` → `re.sub` по правилам
`docs/php_rules.md`, `docs/general_rules.md`, голые `php_rules.md`/`general_rules.md` с
ограничением слева, `.agents/skills/spec-authoring` → `encode("utf-8")`. Порядок тот же, что в
`sed`: сначала «docs/…», потом голые имена; `\r` не трогаем, поэтому CRLF в компонентах остаётся.

`sed`-класс `[^/.[:alnum:]_-]` заменяется явным `[^/.A-Za-z0-9_-]`, а не `\w`: в Python `\w`
по умолчанию Unicode, и кириллица рядом со ссылкой изменила бы поведение. Ограничения на ASCII
достаточно — ссылки в компонентах пишутся ASCII-путями.

Копирование с `cp -p` заменяется чтением источника и записью результата с режимом источника —
внешний `cp` не нужен.

### 6. `merge.py` становится модулем, а не отдельным процессом

Функции переезжают в `kit/merge.py` без изменения алгоритма (отступ, CRLF, однострочность,
сравнение без `./`, только дополнение, атомарная запись). Коды 0/2/3 превращаются в результат
`MergeResult(status=..., added=[...])`, который `install.py` переводит в тот же вывод:
`added: <путь>` в лог, `WARN` + подсказка при 2/3.

Так исчезает тройка «процесс + файл-список + разбор stdout». Функция принимает
`desired: Sequence[str]` напрямую.

### 7. Вывод и ошибки — один модуль

`kit/common.py` повторяет `log/step/ok/skip/warn/die`, `resolve_project_dir` (раскрытие `~`,
канонический путь, отказ от `/` и `$HOME`), `in_project`, `refuse_symlink`. `die` поднимает
исключение `KitError`, а `main` печатает `ERROR:` и возвращает 1 — вместо `exit` из середины
вложенного вызова. Это даёт возможность тестам вызывать шаги напрямую, но CLI-поведение и текст
ошибок не меняются.

### 8. `bootstrap.sh`: минимум правок

Меняются три места: проверка `python3` (рядом с проверкой `git`), вызов
`python3 "$KIT_DIR/install.py"`, и больше ничего. Логика клона, `--offline`, `AGENT_KIT_DIR`,
удаления клона и `AGENT_KIT_EPHEMERAL` остаётся. `--offline` по-прежнему не пробрасывается.

### 9. Тесты на Python

`tests/smoke.py` повторяет сценарии `smoke.sh` и вызывает установку как
`[sys.executable, str(INSTALL), ...]` через `subprocess.run(capture_output=True)`. Хелперы:
`ok/bad/check`, `new_project` (git init), `kit_ext` (копия kit-а с группами `js`/`go` и
`commands/`/`agents/`), `write`. Временный корень — `tempfile.mkdtemp()` в системном temp,
удаляется в `finally`. Проверки `$HOME`/`/` сохраняются и работают через `env`-параметры.
Итог `PASS=n FAIL=m` и ненулевой код при `FAIL > 0`.

Альтернатива — оставить `smoke.sh` — отвергнута: тест был бы единственным `sh`-кодом в проекте
и требовал бы `shellcheck`, который больше не проверяет установку.

### 10. CI

- `dash -n bootstrap.sh` и `shellcheck -s sh bootstrap.sh` — только для пусковой обёртки;
- `python3 -m compileall -q install.py kit tests` — синтаксис всех модулей;
- `python3 tests/smoke.py` — единственный прогон.

Шаги `dash -n`/`shellcheck` по `install.sh` и `lib/*.sh` уходят вместе с файлами.

## Risks / Trade-offs

- **Расхождение поведения при переносе** → тесты переносятся первыми и прогоняются против нового
  `install.py` до удаления `install.sh`; сравнение идёт по тем же проверкам (файлы, вывод, коды).
- **Python 3.9+ на целевой машине** → требование явное в README и `--help`; `bootstrap.sh`
  сообщает об отсутствии `python3` до клонирования. Старые дистрибутивы без `python3` больше не
  поддерживаются — это принято в proposal.
- **Разные версии Python меняют форматирование JSON** → `json.dumps` в `merge` уже сейчас
  отвечает за форму файла; поведение сохраняется, но тесты фиксируют отступ/CRLF/однострочность,
  чтобы регрессия была видна.
- **`os.replace` и симлинки** → запись по симлинку не выполняется: `refuse_symlink` вызывается
  до создания временного файла, временный файл создаётся рядом и заменяет только обычный путь.
- **Остатки `*.tmp.<pid>` при `kill -9`** → `kill -9` не перехватывается; имена с pid не
  пересекаются с файлами kit-а и не подхватываются установкой. При `INT`/`TERM` временные файлы
  удаляются.
- **`bootstrap.sh` остаётся shell** → это осознанно: `curl | sh` — единственный способ запуска
  без предварительной установки. Он не содержит логики установки, только клон и вызов.

## Migration Plan

1. Добавить `kit/` и `install.py`, перенеся логику `lib/*.sh` и `lib/merge.py` с сохранением
   текстов сообщений.
2. Переписать тесты в `tests/smoke.py` и прогнать против `install.py`; все проверки зелёные.
3. Переключить `bootstrap.sh` на `python3 "$KIT_DIR/install.py"` и добавить проверку `python3`;
   прогнать сценарии bootstrap из теста.
4. Удалить `install.sh`, `lib/`, `tests/smoke.sh`; обновить CI на `compileall` и `tests/smoke.py`.
5. Обновить `README.md` и `AGENTS.md`: состав репозитория, требования, команды проверки и запуска.

Откат — `git revert` этого изменения: установка снова идёт через `install.sh`, а уже поставленные
в проекты файлы от версии установщика не зависят, поэтому миграции данных нет.
