# Design

## Context

См. `proposal.md`. Технические ограничения, которые формируют решение:

- Код — строгий POSIX `sh` (`dash -n` в CI). Нет массивов, `local`, `pipefail`, `[[ ]]`.
  Отсюда: списки собираются в файлы во временном каталоге, а не в переменные и не в пайпы.
- `install.sh` подключает `lib/*.sh` через `.`. Публичный контракт — CLI: `install`,
  `--with`, `--dir`, `--dry-run`, `--help`.
- `bootstrap.sh` клонирует kit в `<проект>/.agent-kit` и вызывает `install.sh`; его правки не
  нужны, кроме удалённых флагов.
- Kit ставит файлы в `.agents/` (скиллы и правила) и `.opencode/` (команды и агенты) — это
  каталоги, которые OpenCode обнаруживает в проекте.
- Существующие компоненты: правила (`general_rules.md`, `php_rules.md`), скиллы
  (`conventional-commit`, `spec-authoring`).

## Goals / Non-Goals

**Goals:**

- Одна операция — копирование файлов. Никаких слияний, учёта поставленного и откатов.
- Группы как единственная ось вариативности: `base` + языковые по `--with`.
- Расширяемость без правки скрипта: новый файл в подкаталоге группы просто ставится.

**Non-Goals:**

- Не отслеживаем, что kit поставил раньше (нет манифеста), значит не умеем удалять kit из
  проекта и не показываем расхождения. Удаление — вручную.
- Не правим `opencode.json` — правила подключаются через `AGENTS.md` или руками.
- Не поддерживаем «сохранение локальных правок в файлах kit-а».

## Decisions

### 1. Группы вместо профилей

`components/<группа>/<тип>/…`. Профили `profiles/*.list` удаляются: они дублировали структуру
каталогов строками путей и требовали отдельного парсера.

Альтернатива — оставить `.list`-файлы и научить их списку групп. Отвергнута: каталог сам
описывает группу, а `find` уже даёт полный список файлов. Список групп для валидации и
подсказок получается `for d in components/*/` без нового формата.

### 2. `--with` как единственный селектор

`--with php,js`, повторяемый. Значение режется по запятым и пробелам. `base` добавляется
всегда и не может быть исключён. Валидация до первой записи: собрать список групп, проверить
каждую, при ошибке `die` до создания каталогов.

Альтернатива — `--profile base,php`. Отвергнута: заставляет явно указывать `base` и путает с
прежним одиночным `--profile`.

### 3. Безусловная перезапись, без `cmp`-оптимизаций на уровне решения

Копирование идёт через временный файл в целевом каталоге + `mv` (атомарная замена). `cmp`
перед `mv` остаётся только как оптимизация `mtime`, а не как «не перезаписывать»: содержимое
всегда берётся из `components/`.

`mv` вместо `cp` поверх файла выбран сознательно: `mv` заменяет симлинк, а не идёт по нему,
поэтому запись физически не может уехать за пределы проекта. Плюс перед этим явный
`refuse_symlink` — чтобы ошибка была внятной, а не молчаливой заменой ссылки.

### 4. `target_path` расширяется двумя ветками

```
rules/<x>       -> .agents/rules/<PREFIX>_<x>
skills/<id>/... -> .agents/skills/<PREFIX>_<id>/...
commands/<x>    -> .opencode/commands/<PREFIX>_<x>
agents/<x>      -> .opencode/agents/<PREFIX>_<x>
```

`commands/` и `agents/` — плоские каталоги markdown-файлов (так их читает OpenCode: вложенный
путь становится частью имени команды/агента, а префикс уже защищает от коллизий). Поэтому
вложенность там не разворачиваем: `commands/**` — ошибка компонента, как и раньше для мусора
вне `rules/` и `skills/`.

### 5. `render.sh` сокращается до подстановки ссылок

Остаётся `refs`: `docs/general_rules.md`, `docs/php_rules.md`, `.agents/skills/spec-authoring`
→ префиксные пути. Уходят `neutralize` (нужен был, чтобы `base` не ссылался на отсутствующие
PHP-правила) и `stamp` (метаданные версии были нужны `adopt` и `status`).

Вместо `neutralize` правится сам компонент: в `components/base/rules/general_rules.md`
упоминание `docs/php_rules.md` убирается, а PHP-специфика описывается в группе `php`. Так
`refs` остаётся единственным режимом, а текст правила не зависит от выбранных групп.

### 6. `AGENTS.md` — единственная «умная» часть

`[ -e ] || [ -L ]` → `SKIP`. Иначе рендер шаблона и `mv`. Симлинк считается существующим
файлом (спек `project-agents-file`): не пишем и не разыменовываем.

### 7. Что удаляется целиком

- `lib/merge.py` (341 строка) и `snippets/openspec.rules.tsv` — вместе с шагами установки.
- `lib/manifest.sh` — вместе с `status`/`uninstall`.
- `strip_kit_metadata`/`restore_refs`/`adopt` — учёт версий больше ни на что не влияет.
- Хеши и `sha256_of` — единственный потребитель был манифест. `sha256_of` уходит из
  `lib/common.sh`, `sha`-хелпер из `tests/smoke.sh` тоже.
- Флаги `--keep-modified`, `--force`, `--no-agents`, `--no-openspec`, `--offline` в
  `install.sh`. `bootstrap.sh` продолжает принимать `--offline` (он про обновление клона) и
  пробрасывает остальные аргументы; лишние флаги теперь просто не доходят до `install.sh`.

### 8. `.gitignore` не трогается

Раньше строка `.agent-kit/` дописывалась, чтобы клон `bootstrap.sh` не засорял индекс. Теперь
клон удаляется после установки, поэтому править чужой файл незачем: установка его не читает и
не меняет. Это убирает последнюю правку чужих файлов.

### 9. CI и тесты

`dash -n` + `shellcheck` по всем скриптам остаются. Шаг `py_compile` уходит вместе с
`merge.py`. `tests/smoke.sh` переписывается: проверки слияний/дрейфа/`--keep-modified`/
`--force`/`uninstall`/`adopt` заменяются проверками групп, перезаписи, идемпотентности,
новых типов компонентов и границ записи. Тест больше не создаёт `opencode.json`.

## Risks / Trade-offs

- **Потеря локальных правок в файлах kit-а** → это осознанное следствие «просто перезаписать».
  Митигация: префикс в именах и явное предупреждение в README/`AGENTS.md`, что правки в
  префиксованных файлах не живут. Пользователь, которому нужно своё, кладёт файл без префикса.
- **Нельзя удалить kit одной командой** → удаление вручную по списку каталогов. Взамен нет
  манифеста, который сам может рассинхронизироваться. Митигация: README перечисляет ровно те
  каталоги, которые создаёт kit (`ls .agents`, `ls .opencode`).
- **`opencode.json` больше не подключает правила автоматически** → в проекте, где `AGENTS.md`
  уже был, правила не подхватятся сами. Митигация: установка печатает готовые пути для
  `instructions[]`; `AGENTS.md` из шаблона ссылается на правила.
- **Имя команды под префиксом** → `/alxmrz_kit_<x>` длиннее, чем `/x`. Митигация: префикс —
  цена того, что kit не затирает одноимённые пользовательские команды; осознанный выбор.
- **Миграция существующих установок** → манифест и штампы останутся в проектах, где kit уже
  стоял. Ничего не ломается: файлы просто перезапишутся/останутся. Старый `.agents/.alxmrz_kit_manifest.json`
  после обновления не обновляется и его можно удалить. Отдельный шаг очистки не делаем —
  иначе снова появляется код, который знает про старое состояние.

## Migration Plan

1. Сразу обновить `AGENTS.md` (kit-а) и `README.md` — там описан порядок проверки и состав.
2. Переложить `components/` в группы, удалить `profiles/`.
3. Переписать `install.sh`, `lib/components.sh`, `lib/render.sh`, `lib/common.sh`.
4. Удалить `lib/manifest.sh`, `lib/merge.py`, `snippets/openspec.rules.tsv`.
5. Переписать `tests/smoke.sh`, прогнать проверку из `AGENTS.md`.
6. Откат — revert коммита: kit ставится с нуля, внешних артефактов и миграций данных нет.
