# Proposal

## Why

Сейчас установка kit-а — это не «положить файлы», а «аккуратно дописать чужую разметку»:
`opencode.json` и `openspec/config.yaml` правятся через `lib/merge.py`, из-за чего в
`install.sh` живут ветки на комментарии, `rules: {}` и нестандартные отступы, а вокруг
выросла вся инфраструктура учёта: манифест, `status` с проверкой слияний, `uninstall` с
откатом правок, `adopt`, флаги `--keep-modified`/`--force`/`--no-openspec`, закрепление
хешей и штамп версии в каждом скилле. Всё это обслуживает слияния и локальные правки,
хотя задача — «положить в проект файлы для ИИ-агента». Новые типы компонентов (команды,
агенты) в эту схему вообще не вписываются.

Нужно вернуться к простой модели: kit — это набор файлов, которые при запуске копируются в
проект, существующие одноимённые файлы перезаписываются. Языковая специфика подключается
множественным выбором групп правил. Единственное исключение — `AGENTS.md`: он создаётся
один раз из шаблона и дальше принадлежит проекту.

## What Changes

- **BREAKING**: установка ничего не сливает. Удаляются `lib/merge.py`,
  `snippets/openspec.rules.tsv`, шаги `opencode.json` и `openspec/config.yaml`, флаг
  `--no-openspec`, а также `--keep-modified` и `--force`: файлы kit-а перезаписываются
  безусловно.
- **BREAKING**: удаляются `status`, `uninstall`, `adopt` и `.agents/.alxmrz_kit_manifest.json`.
  Kit больше не ведёт учёт поставленного; остаётся одна команда — установка. Вместе с ними
  уходят `lib/manifest.sh`, хеширование и `strip_kit_metadata`/`restore_refs`.
- Компоненты раскладываются по группам: `components/base/` (всегда) и `components/<язык>/`
  (подключаются флагом `--with php,js`). Группа — каталог с подкаталогами `rules/`,
  `skills/`, `commands/`, `agents/`; наличие подкаталога необязательно.
- Появляются новые типы компонентов: команды (`.opencode/commands/`) и агенты
  (`.opencode/agents/`). Сейчас файлов там нет, но поддержка есть: новый файл
  подхватывается без правки скрипта. Скиллы и правила остаются в `.agents/skills/` и
  `.agents/rules/`.
- `AGENTS.md` закрепляется как требование: создаётся из шаблона, только если файла нет;
  существующий не читается и не меняется. Флаг `--no-agents` убирается — поведение
  безусловное.
- Штамп `metadata: alxmrz-kit` в скиллах убирается: без учёта версий он ничего не сообщает,
  а `adopt`, ради которого он существовал, больше нет.
- `.gitignore` больше не правится: клон `bootstrap.sh` удаляется после установки, поэтому
  игнорировать в нём нечего.
- `bootstrap.sh` не меняется: он клонирует kit в `.agent-kit/` и вызывает `install.sh`.

## Capabilities

### New Capabilities

- `component-install`: что и куда kit кладёт в проект — группы компонентов и их выбор,
  раскладка целевых путей для правил, скиллов, команд и агентов, безусловная перезапись,
  границы записи (только проект, без симлинков), идемпотентность повторного запуска и
  подсказка о том, как подключить правила, если `AGENTS.md` уже существовал.
- `project-agents-file`: шаблонный `AGENTS.md` — создаётся один раз, если файла нет,
  и никогда не перезаписывается.

### Modified Capabilities

Нет: в проекте ещё нет ни одной капабилити в `openspec/specs/`.

## Impact

- `install.sh`: остаётся `install` (и `--dry-run`); удаляются `status`, `uninstall`, `adopt`,
  `prune_components`, `install_opencode_json`, `install_openspec_rules`, `write_manifest`.
- `lib/components.sh`: группы вместо профилей; `target_path` учит `commands/` и `agents/`.
- `lib/render.sh`: остаётся только подстановка ссылок; уходят `neutralize`, `stamp`,
  `apply_profile_rules`.
- `lib/manifest.sh` и `lib/merge.py`: удаляются; из CI уходит `py_compile`.
- `components/`: раскладка `components/base/…` и `components/php/…`; `profiles/*.list` удаляются.
- `components/rules/general_rules.md`: убирается упоминание `docs/php_rules.md` — иначе
  базовый набор остаётся с битой ссылкой на неподключённую группу.
- `tests/smoke.sh`: переписывается под новую модель (перезапись, идемпотентность, группы,
  новые типы компонентов, границы записи).
- `README.md`, `AGENTS.md` (kit-а), `snippets/AGENTS.md.tmpl`: описание установки без слияний.
- Последствие для пользователя: правила из `.agents/rules/` больше не попадают в
  `instructions[]` автоматически. Их подключает `AGENTS.md` из шаблона, а если `AGENTS.md`
  уже был — установка печатает готовые пути для ручного добавления.
