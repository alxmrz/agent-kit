# Design

## Context

См. `proposal.md` — Why. Ограничения, которые формируют решение:

- Всё, кроме одного шага, — строгий POSIX `sh` (`dash -n`, shellcheck в CI). Правка JSON на `sh`
  означала бы собственный парсер: отступы, запятые, экранирование строк.
- Установка идемпотентна и сравнивает результат через `cmp`: неизменённый файл не должен
  перезаписываться, иначе у него дёргается mtime.
- Запись в проект атомарная (временный файл + `mv`) и только внутрь проекта; симлинки на месте
  целевых файлов отвергаются.
- Kit не ведёт учёт поставленного: при смене `--with` старые файлы правил остаются в проекте.

## Goals / Non-Goals

**Goals:**

- Правила `base` и выбранных групп работают сразу после установки, без ручной правки конфига.
- Правка `opencode.json` минимальна и предсказуема: только дополнение `instructions[]`.
- Отсутствие `python3` деградирует до прежнего поведения (подсказка), а не ломает установку.

**Non-Goals:**

- Не поддерживаем JSONC (`opencode.jsonc`): комментарии требуют настоящего парсера, а два конфига
  рядом сделали бы правку `opencode.json` бессмысленной.
- Не удаляем пути правил из `instructions[]` при смене `--with`: файлы правил тоже не удаляются,
  и чистка конфига создала бы расхождение с содержимым проекта.
- Не правим другие ключи `opencode.json` (модели, агенты, permissions).

## Decisions

### 1. python3 для слияния JSON

`lib/merge.py` читает конфиг, добавляет отсутствующие пути, пишет через временный файл. Python
выбран, потому что это единственный доступный на целевых машинах инструмент с настоящим
JSON-парсером; в истории kit-а такое решение уже было. Альтернатива — `sh`/`awk` по строкам: ломается
на вложенных `instructions[]`, `],` и экранированных путях, а ошибка разбора портит чужой конфиг.
Альтернатива — `jq`: ещё одна зависимость без выигрыша.

Зависимость необязательная: шаг проверяет `have python3` и при отсутствии печатает подсказку.
`--dry-run` показывает план и не вызывает python3.

### 2. Только дополнение, без удаления

Слияние добавляет пути и никогда не убирает записи. Причина: kit не удаляет файлы правил при смене
`--with` (учёта поставленного нет), поэтому удаление строки из конфига оставило бы файл без
подключения — и повторный `--with` снова его добавлял бы. Цена: после смены набора групп в
`instructions[]` остаются пути прежних групп. Это безопасно (файлы на месте) и видно в диффе.

### 3. Сохранение форматирования

Отступ определяется по первой непустой строке файла; однострочный JSON остаётся однострочным;
наличие `\r\n` переносится на результат. Новый файл пишется с отступом 2. Это не «красиво», а
требование к чужому репозиторию: первый запуск не должен давать шумный дифф.

### 4. Симлинк и JSONC — не ошибка установки

`opencode.json` может быть симлинком (например, на общий конфиг команды). Писать по нему нельзя,
но и ронять установку из-за одного файла нельзя: компоненты уже поставлены. Поэтому шаг печатает
`SKIP`/`WARN` и подсказку с путями. Так же ведёт себя `AGENTS.md`-симлинк.

### 5. Список путей берётся из уже собранных целей

`instructions_list` фильтрует `$STATE_DIR/targets` по `^\.agents/rules/` и добавляет `./`. Так
список всегда совпадает с фактически поставленными файлами, включая правила новых групп, и не
требует отдельного перечисления групп в коде.

## Risks / Trade-offs

- **Правило группы исчезло из kit-а, а путь остался в конфиге** → путь ведёт на существующий файл
  (kit не удаляет файлы), агент читает устаревшее правило. Митигация: это видно в диффе при
  обновлении; удаление делается вручную.
- **Пользователь ждёт синхронизации `instructions[]` с набором групп** → README и `AGENTS.md`
  явно говорят «только дополняет». Альтернатива отвергнута в решении 2.
- **python3 нет** → правила не подключены автоматически. Митигация: печатается готовый список
  путей, установка не падает.
- **Нестандартный JSON (`instructions` — не массив строк)** → файл не меняется, печатается
  подсказка. Мы не угадываем, как переписать чужую структуру.
- **Однострочный конфиг с добавлением** → вся строка перегенерируется `json.dumps`: порядок ключей
  сохраняется, но пробелы внутри объектов могут измениться. Приемлемо: файл уже без форматирования.

## Migration Plan

1. `lib/merge.py` + `have` в `lib/common.sh`.
2. Шаг `install_opencode_json` в `install.sh` вместо `print_instructions_hint` по условию
   «AGENTS.md уже был».
3. Тесты в `tests/smoke.sh`: создание, дополнение чужого конфига, отступ, CRLF, однострочность,
   идемпотентность, JSONC, симлинк, отсутствие python3.
4. Документация: `README.md`, `AGENTS.md`, CI (`py_compile`).

Откат — вернуть печать подсказки и удалить `lib/merge.py`; созданные `opencode.json` остаются в
проектах, их удаляют вручную.
